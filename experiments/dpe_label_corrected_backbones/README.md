# DPE with corrected Waterbirds labels on fresh backbones (Kaggle, T4 x2)

Notebook: [`dpe_label_corrected_backbones_kaggle.ipynb`](dpe_label_corrected_backbones_kaggle.ipynb)
(generated by `build_notebook.py` from `runner.py` and `summarize.py`; edit those, then rebuild).

## Question

The ACIIDS draft shows that refitting DPE on corrected validation labels raises corrected-test
WGA by +2.48 pp on our seven saved backbones (`results/dpe/label_correction_20261115`). Those
backbones were inspected repeatedly and trained on the official training labels. This run
(1) replicates the validation-label effect on fresh backbones with a contrast declared before the
run, and (2) measures what correcting the 72 training labels adds.

Design: backbone training labels {official, corrected} x DPE validation labels {official,
corrected} x DPE head seeds {s, s+1000, s+2000}, backbone seeds 5-8, every model scored on
official and corrected test labels. Primary contrast (declared in `summarize.py`): official
backbone, corrected minus official validation labels, on corrected test labels.

Pipeline: the audited runner of `noerula/dpe-reproduction` (SubpopBench ERM with default
hyper-parameters, 5,001 steps; the authors' unmodified DPE `main.py`, 15 heads, `wga_val`), plus
a `--label-set` switch. `runner.py` differs from that runner only in lines marked `LABEL-SET` or
`SMOKE`.

## How to run

1. Kaggle -> Create -> New Notebook -> File -> Import Notebook -> upload the `.ipynb`.
2. Settings: Accelerator **GPU T4 x2**, Internet **on**.
3. Recommended: Add Input -> Notebook Output Files -> `noerula/dpe-reproduction`. The notebook then
   reuses the official backbones of seeds 5 and 6 (SHA-256 checked) and saves two trainings.
4. **Save Version -> Save & Run All (Commit)**. The run continues with the browser closed.

The notebook installs the pinned environment (~10 min), runs a smoke test (~20 min; it stops the
run if anything is broken), then schedules jobs on both GPUs in priority order:

1. corrected backbones for seeds 5, 6 (official ones reused or retrained);
2. cross-label DPE fits for seeds 5, 6;
3. official and corrected backbones for seeds 7, 8 and their cross-label fits;
4. two extra head seeds for every backbone and regime.

No job starts unless it is expected to finish by `TIME_LIMIT_HOURS` (11 h), so the version saves
before Kaggle's 12 h limit; lower-priority head seeds are dropped first. Rough expectation: six
backbone trainings (~1.5-2.5 h each, two at a time) and ~40 DPE fits (~5-10 min each).

## Outputs

`/kaggle/working/dpe-labels/report/REPORT.md` and `summary.csv` (refreshed after every job), and
`label-corrected-evidence.zip` (manifests, logs, metrics, per-image test predictions, one feature
cache per backbone). Backbone weights are not bundled.

## Local checks done before the run

* `tests/test_label_corrected_summarize.py`: scoring on both label sets and the contrast table.
* The notebook's scheduler and smoke-test cells were executed locally against a fake runner,
  including a simulated training failure (its dependent jobs are skipped, the report still builds).
* `runner.verify_data` accepts the official and corrected metadata built by the notebook's own
  correction code and rejects a mismatched label set.

Not tested here: GPU training, the Kaggle file layout of attached notebook outputs, run times.

## Follow-ups on CPU once the bundle is downloaded

The bundled features allow, without GPU time: DFR-lite on the fresh backbones under both label
sets; cross-fitting and the threshold controls under corrected labels; and a declared test of
whether head-disagreement combiners add information beyond the mean score when the labels are
correct (a proposal raised in review of the draft).
